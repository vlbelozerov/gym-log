Версия: ветка `feature/training-plan-8-weeks`. Не объединять PR и не считать приложение настроенным для реальных данных только на основании CI. Использовать отдельный тестовый аккаунт и не удалять рабочие записи.

## Email-регистрация (Supabase Auth)

1. Supabase Dashboard → Authentication → Providers → Email: включить Email и **Confirm Email**, если нужна проверка адреса.
2. Authentication → URL Configuration: **Site URL** = постоянный production HTTPS URL приложения; в **Redirect URLs** добавить тот же адрес. Для тестового Preview — точный Preview URL; для локальной разработки `http://localhost:5173`.
3. Для встроенной почтовой отправки можно тестировать только адреса, разрешённые для команды Supabase, с низким лимитом. Для произвольных получателей настроить **Custom SMTP** (Authentication → SMTP / Email settings; точное расположение зависит от панели), адрес отправителя, порт, хост, пользователя и пароль — непосредственно в Supabase, не в `VITE_*`.
4. Проверить email template «Confirm signup» и «Reset password»: ссылки должны учитывать переданный `RedirectTo`, если используется отдельный адрес Preview.
5. В приложении выбрать **Регистрация**, указать email и пароль, открыть письмо подтверждения, перейти по ссылке; после этого проверить вход.
6. Нажать **Не помню пароль**, открыть письмо и установить новый пароль; проверить вход с новым паролем.
7. Проверить, что один пользователь **не видит** журнал другого (RLS) и не может обратиться к чужому документу; автоматический PostgreSQL-тест проверяет RLS, но дополнительно полезна ручная проверка из двух тестовых учётных записей.

## Известные ограничения текущей версии

- Нет автоматического слияния правок между параллельно открытыми устройствами; не редактировать один журнал одновременно.
- JSON журнал ограничен 8 МБ. Изображения упражнений не загружаются в журнал.
- Пошаговые текстовые инструкции присутствуют для стандартной библиотеки. **Сгенерированные иллюстрации пока не внедрены в приложение**.
- Режимы интервального бега сохраняют запланированную структуру и общий фактический результат; фактический результат **каждого интервала отдельно** пока не фиксируется.
- Суммарная длительность повторяемых беговых блоков может не совпадать с общей целевой длительностью. Последний цикл подгоняется вручную.
- Нет полноценного E2E с реальной Supabase и SMTP в CI; нужны описанные ручные проверки.

Проверить production deployment, регистрационный редирект, создание тренировки и облачную синхронизацию **ещё раз на production**. Не очищать браузерные данные при неподтверждённом статусе отправки.
